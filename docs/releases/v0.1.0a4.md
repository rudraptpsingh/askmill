# v0.1.0a4: leased structured candidate responses

## Problem and outcome

The supported Ollama transport omitted `format`, preventing a consumer from
requesting schema-constrained semantic candidates through AskMill's lease and
receipt boundary. a4 forwards an explicitly pinned response schema using
request/result v2. Current profiles and v1 calls remain compatible. The contract,
failure behavior and consumer commands are in [STRUCTURED_OUTPUTS.md](../STRUCTURED_OUTPUTS.md).

## Phases and validation gates

1. **Reproduce and scope.** Confirm the missing native `api/chat` field, inspect
   the consumer's exported schema and verify official Ollama support. Outcome:
   a generic response contract; document/source extraction stays consumer-owned.
2. **Implement the opt-in contract.** Pin the schema, reject unsupported
   schema/provider/runtime combinations, forward `format` through the existing
   worker and validate literal output offline. Outcome: distinct completion,
   schema validity and unverified acceptance, with failed output retained.
3. **Regress existing and new paths.** Exercise payload forwarding, changed
   schema cache identity, replay validation, mutation rejection, invalid/truncated
   retention, duplicate keys, output budgets, offline schema rejection, CLI
   exit codes, mixed warm batches and actual stdio MCP. Outcome: passing local
   suite plus unchanged PDF2Data native/legacy integration checks.
4. **Qualify the package.** Build wheel/sdist, install the wheel in a fresh
   environment and test imports from site-packages, v1/v2 and published PDF2Data.
   Attempt one synthetic real-model structured call through shared host leases;
   record a busy lease as pending rather than disrupting delivery.
5. **Merge and publish.** Main CI must pass, then publish a new immutable tag,
   wheel/sdist SHA256 and sanitized validation evidence. Outcome: a reproducible
   release for an explicit consumer pin update; no replacement of old assets.
6. **Consumer readoption.** Route the concrete release to Central Router.
   Outcome: AskMill released; PDF2Data acceptance remains `adoption_pending`
   until its owner installs the pinned artifact and checks source semantics.

The existing default launcher, profiles and running jobs are not silently
upgraded by this release. A separate versioned validation environment is used.
No fallback, model download, source approval or consumer rollout is implied.

Local source validation: 72 passed, one optional skip, including 30 new
structured cases. Clean installed-wheel core: 67 passed, two optional skips.
The real installed-wheel Gemma 4 E4B check passed JSON Schema validation,
synthetic source-ID assertion, receipt replay and acknowledged settlement.
Versioned release assets record final package checksums, public PDF2Data wheel
compatibility, main CI and the sanitized hardware receipt summary.
