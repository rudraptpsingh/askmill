# v0.1.0a3: model-specific configuration and researched task profiles

## Shared capability issue

v0.1.0a2 hard-coded thinking=false and temperature=0 for Ollama, exposed no
context setting and used one MLX template path. A supplied generation field
failed strict Profile validation. This prevented faithful configuration of
models selected from public research. The issue was routed to Central Router.

## Change

The explicit askmill.profile.v2 format adds bounded generation settings:
thinking (boolean, supported level or provider default), temperature, top-p,
top-k, Ollama context tokens and an optional model-aware MLX template. v1
profiles retain their serialized wire keys and provider behavior.

Ollama thinking values are checked against model metadata before sending
input, preventing silent fallback to an unsupported level. Resolved provider
defaults enter runtime identity. Generation settings enter profile/cache
identity. Reasoning-only token-limited replies produce retained incomplete
results, never fabricated final answers.

Unsupported MLX context allocation and string reasoning levels are rejected.
The old request/result wire formats, source acceptance and lease ownership
are preserved. The default installed binary is adopted from an immutable
wheel rather than an editable checkout.

## Validation and rollout

Eight new generation/compatibility checks cover actual payload propagation,
cache separation, rejection before inference, reasoning-only truncation,
model-aware MLX templates and v1 wire keys. The complete suites have 37 core
checks, 41 with published PDF2Data, and 42 with the local legacy consumer.

Real selected-model calls and published PDF2Data source reopening passed.
Selection and limitations are in MODEL_SELECTION_2026-11-01.md. The host's
profile adoption uses pinned models and shared GPU leases. Other consumers
retain their existing package/profile pins until their owners update and
check acceptance; their adoption remains pending.

Release assets include the wheel, source archive, SHA256SUMS and validation
metadata. Previous tags, wheels and receipts remain immutable.


Central Router reproduced a deployment mismatch during staging: the installed
a2 executable could see newly written v2 host profiles and rejected them before
inference. The candidate registry was moved out of the live path immediately,
leaving the v1 baseline available. Promotion now installs a versioned immutable
environment first, checks every staged profile with that installed executable,
switches the launcher, and only then atomically publishes the registry.
The a2 environment and a2 profile snapshot remain available for rollback and
in-flight pinned work. Doctor reports runner_version; --version is available.
Installed-executable tests exercise both v1 and v2 profiles.


PDF2Data read-fields accepts an explicit --prompt for specialist readers and
retains that actual execution prompt in the imported raw reading. Its default
consumer prompt is unchanged. The native CLI test verifies the prompt survives
through the installed command and consumer import. With Paddle, OCR: avoided
duplicate lines seen with the generic transcription instructions.
