# AskMill 0.1.0a8 candidate

Corrects three independent-review findings in a7's opt-in embedding engine.
Cleanup and monitor cancellation authenticate the original provider PID and
creation time before adopting children or signalling its process group; an
unknown/reused parent leaves settlement uncertain. The context gate executes
from its exact verified source bytes rather than an unpinned bytecode cache.
The complete pinned model/tokenizer/provider/runtime closure is rechecked after
provider termination and again after host callbacks before delivery; any drift
retains evidence and refuses the result.

This is a candidate for independent re-review, not an accepted live provider.
The current source authority, durable budget gate, exact profile and inputs,
consumer acceptance and actual model/runtime qualification remain separate.
No old grant or namespace is reused, and existing a7/a6 installations remain
unchanged. See [embedding setup](../EMBEDDINGS.md).

Validation: 40 affected source tests, 18 isolated installed-wheel controls and
17 adapted independent software replay controls passed. The PID-reuse control
sent no OS signals; runtime drift produced no result. The gate loader control
uses a benign stale bytecode cache. No real provider or embedding was started.
